# 打包与升级

简体中文 · [繁體中文](打包與升級.zh-Hant.md)

> **Important · 未签名**：发行包的启动器没有代码签名。首次运行 Windows SmartScreen
> 会提示「Windows 已保护你的电脑」→「更多信息」→「仍要运行」。分层布局让启动器内容稳定，
> 不再每次更新都换 EXE，有利于信誉累积；但这**不能替代签名**，正式分发需要代码签名证书。

## 为什么是 onedir

| 形态 | 启动 | 更新 | 代价 |
|---|---|---|---|
| onefile（旧） | 每次解压约 200 MB 到 `%TEMP%` | 整包替换 | 冷启动慢、Defender 扫临时目录、SmartScreen 信誉每次归零 |
| onedir 分层（当前） | 直接加载已就位的文件 | 只替换 EXE + `_internal/` + `manifest.json` | 是文件夹，不能只拷 EXE |

去掉 pythonnet 之后，当年迫使 onefile 的 MOTW 失败链（散落 DLL 被标记、.NET 拒载）已不存在。
路径规则集中在 `app_paths.py`，详见 [架构说明](架构说明.md) §2。

## 目录契约

```text
QwenASR-WebView.exe    启动器                    ┐
_internal/             程序本体、依赖、前端      ├─ 受管内容（manifest 覆盖，更新时替换）
manifest.json          内容寻址清单（SHA256）    ┘
ov_models/ subtitles/ longform_state/ ffmpeg/
crispasr/ chatllm/ GPUModel/ settings.json
app.lock app.prev/ 使用说明.txt build_manifest.json   ── 用户数据 / 辅助文件（更新时不动）
```

`manifest.json` 只记录受管内容。`USER_DATA` 集合在 `release_manifest.py` 中定义，
`build_manifest()` 会明确跳过它们 —— 用户的 4.4 GB 模型与断点永远不会被枚举或覆盖。

## 构建

```bash
python build_release.py --version 2.0.0 --sha <short-sha>
```

`build_release.py` 依次：`--onedir` 打包 → 整树复制到 `release_pkg/QwenASR-WebView/` →
**`slim_openvino()` 精简 OpenVINO** → 生成 `manifest.json` → `verify_onedir()` 检查关键条目 → 组 ZIP。

### 体积：哪些是必要的，哪些删得掉

模型权重不内嵌（1.2～4.4 GB，按需下载），所以包体主要由运行时依赖构成。当前可删的只有
OpenVINO 的**未使用组件**：

| 组件 | 体积 | 是否需要 |
|---|---|---|
| `openvino_intel_cpu_plugin.dll` | 40.5 MB | **必需**（唯一推理设备） |
| `openvino.dll` + 依赖插件 + `tbb*.dll` | ~26 MB | **必需** |
| `openvino_intel_gpu_plugin.dll` | 30.9 MB | 不需要：本项目恒用 CPU |
| `openvino_intel_npu_plugin.dll` | 4.0 MB | 不需要 |
| TensorFlow / ONNX / PyTorch / Paddle / TFLite / JAX 前端 | ~14 MB | 不需要：只加载 IR |
| `*.lib`（导入库）、`cache.json`（设备缓存） | 16.5 MB | 不需要：编译期产物 / 可重建 |
| `include/`（C++ 头文件）、`*.pyi`（类型存根） | 6 MB | 不需要：写代码/编译时才读，`import` 不碰 |

实测 `openvino/` 目录 **132 MB → 61 MB（省 71 MB）**。保护措施：

- 认不出目录布局（缺 CPU 插件 / 核心 DLL / IR 前端）就**整体跳过**，宁可不动也不打坏包；
- `tools/verify_package.py` 的 `check_openvino_slim()` 断言 CPU 路径在位、GPU/NPU 不在位，
  打包门禁会拦住两边——删过头（起不来）和没删（白胖）；
- `python build_release.py --no-slim` 一键回退完整组件，排查「设备列表少了 GPU」时用。

还有两项**刻意不删**：`onnxruntime`（`app.py` 无条件导入，说话人分离依赖它，删了程序起不来）、
`tokenizers`（`--collect-all`，Qwen 分词器运行时必需）。

界面层也做过一次隔离：`app.py` 的 Tk 界面（customtkinter + tkinter + tcl/tk）在 WebView 版里
完全用不到，以前因顶层 `import customtkinter` 被静态分析连带收进包；现在由环境变量
`QWENASR_WEBVIEW_BUILD=1` 隔离，`python app.py` 不受影响。
`tools/verify_package.py` 额外校验分层结构、`_internal/` 体积、manifest，以及
`check_layout()` 定义的目录契约：用户数据目录必须在启动器旁，纯用户数据目录不得进入
`_internal/`，`_internal/ov_models/` 则允许且只允许随包 VAD / Mel 只读资源
（同名双用途目录，详见 [架构说明](架构说明.md)）。这套契约由 `tests/test_verify_package.py`
在 CI 与打包前回归中覆盖，避免「包已经打出来了、校验才失败」。

## 校验 / 差量 / 更新 / 回滚

```bash
# 校验发行包是否被改动
python release_manifest.py verify --root release_pkg/QwenASR-WebView

# 看两个版本之间到底要传哪些文件
python release_manifest.py diff --old <旧包> --new <新包>

# 安装新版本（自动备份旧版到 app.prev/，用户数据原样保留）
python release_manifest.py apply --new <新包> --install <安装目录>

# 出问题就回滚
python release_manifest.py rollback --install <安装目录>
```

`apply` 先用 `verify` 校验新包，不通过就**在改动任何文件之前**抛错。
替换过程中若复制失败会自动调用 `rollback()`。`app.prev/` 保存上一版的 EXE、
`_internal/` 与 `manifest.json`。

`diff` 按 SHA256 比较，输出 `added / changed / removed / unchanged` 与 `changedBytes`。
**自动更新策略（已定案：A 方案）**：主线 WebView 版「检查更新」只打开发行页，由使用者手动下载 ZIP 覆盖；不比对版本、不下载、不替换。`updater.py` 里那套整包自动更新属于停更的 CTk 版，WebView 不调用；`release_manifest.py` 的差量分发是独立命令行工具（`verify` / `diff` / `apply` / `rollback`），**未接入 UI，也未接入 `updater.py`**。因此准确说法不是「没有自动更新机制」，而是「不投入把差量工具接进主线、替换 CTk 遗留机制的整套工程」。在未签名 + 上游无 License 的前提下，整套改造（需重写 `updater.py`、Release 附 manifest、前端进度/重启 UI、helper 进程处理运行中文件锁、代码签名与密钥管理、Windows 实机回归）风险大于收益，故维持 A 方案。

## 平滑升级（G4）

`tests/test_release_manifest.py` 用真实文件系统验证：更新前写入 `settings.json`、
`subtitles/*.srt`、`ov_models/*.bin`、`longform_state/checkpoint.json`，
`apply` 后逐项断言内容不变，再 `rollback` 断言旧 payload 恢复且用户数据仍然完好。
这是「旧设置 / 旧模型目录 / 旧断点无缝接管」的可复现证据。

## 冷启动基准（G6）

```bash
python app_webview.py --selftest
```

输出一行 JSON：`constructMs`、`serverStartMs`、`healthRoundTripMs`、`resourceResolveMs`、
`layout`、`frozen`。无 GUI 依赖的环境会把 server 部分标注为 `skipped`，仍能当 smoke test 用。

**边界**：不包含 OS 进程创建、窗口创建、Edge 启动。那些只能在目标 Windows 机器上用
「双击 → 窗口出现」计时。onedir 相对 onefile 的冷启动收益目前**未实测**。

## 签名与 SmartScreen（G8/G9）

- 现状：**未签名**。EXE 由 PyInstaller 生成，未走 Authenticode。
- 用户操作：SmartScreen 提示时点「更多信息」→「仍要运行」；不要运行来源不明的同名 EXE。
- 缓解：启动器内容稳定 → 同一文件的信誉可累积；`manifest.json` 让用户可自行核对 SHA256。
- 正式方案：OV / EV 代码签名证书 + `signtool sign /fd SHA256 /tr <timestamp> /td SHA256`，
  并对 ZIP 附一份 SHA256 校验和。**这一步还没做**，属于发行流程待办。
- 请勿只拷走 `QwenASR-WebView.exe`；缺少 `_internal/` 会直接启动失败。
