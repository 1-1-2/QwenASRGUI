# 架構說明

[简体中文](架构说明.md) · 繁體中文

本文描述目前程式碼的**實際行為**，供後續整理專案首頁時作為素材。不包含開發計畫、
排期或待辦事項；這些內容只在本機維護。

## 1. 視窗策略

啟動器 `app_webview.py` 先在本機 `127.0.0.1` 起一個隨機連接埠的
`WebViewServer`，再開啟瀏覽器視窗；前端只透過 HTTP 與 SSE 和後端溝通。

| 路徑 | 觸發條件 | 依賴 |
|---|---|---|
| Edge `--app` + `--inprivate` | **預設** | 系統內建 Microsoft Edge |
| 原生 WebView2 視窗 | 原始碼安裝時設 `QWENASR_NATIVE_WINDOW=1` | pywebview + pythonnet + .NET |
| 預設瀏覽器 | 系統沒有 Edge 時 | 任意瀏覽器 |

以前預設走原生 WebView2 視窗。散落的 DLL 從 ZIP 解壓後繼承
Mark-of-the-Web 標記，.NET 會拒絕載入被標記的 assembly，導致 pythonnet 失敗、
視窗靜默回退。當時的解決辦法是把全部內容打進單一 EXE（onefile），讓執行期
解壓到 `%TEMP%` 從而不帶標記。

現在預設走 Edge `--app`，根本不載入 .NET assembly，這條失敗鏈不再存在。
發行包因此不再捆綁 `webview` / `pythonnet` / `clr_loader`；`build_release.py`
把它們放進 `EXCLUDE_MODULES`。標題列配色 `_decorate_window_async()` 對兩種視窗
都適用，程式碼原樣保留。

## 2. 打包形態

目前發行包仍由 `build_release.py` 以 PyInstaller onefile 建置，但內容已按職責
區分，為後續分層留出餘地：

```text
QwenASR-WebView.exe   CPython 執行期 + 全部 .py + OpenVINO / ONNX Runtime / 音訊原生庫
  ├─ models.json      模型下載清單的單一事實來源（隨 --add-data 進包）
  ├─ prompt_template.json / mel_filters.npy / silero_vad_v4.onnx
  └─ webview_assets/  前端 HTML / JS / CSS
ffmpeg/ffmpeg.exe     選用，隨包附上
ov_models/            模型權重（首次啟動按需下載，不內嵌）
subtitles/            輸出 SRT
longform_state/       中斷點與逐段 JSONL
settings.json         持久化設定
```

`model_catalog.catalog_path()` 在凍結環境下先查 `_MEIPASS`、再查 EXE 同目錄，
因此同一個包在未分層的 onefile 與未來的分層目錄裡都能工作。

EXE 體積主要來自 CPython 標準庫、OpenVINO CPU plugin 與算子庫、ONNX Runtime、
NumPy / SciPy 的原生擴充及 GUI 依賴。專案自身程式碼和前端只佔很小一部分。
模型權重（0.6B 約 1.2GB / 1.7B 約 4.4GB）刻意不內嵌。

`verify_archive()` 讀取 PyInstaller CArchive 目錄表，確認動態匯入的模組確實
進包；`model_catalog.py` 與 `models.json` 也在必要條目裡。函式內動態 import
的模組若漏列，不會在啟動時報錯，而是點到對應功能才 `ImportError`，所以這項
校驗是建置時的硬性檢查。

## 3. 統一串流資料流

所有輸入（GUI 單檔、批次、CLI、區網 API）都走同一條 `LongformRunner`
路徑，不再按時長分成兩套邏輯。

```text
音訊 / 影片檔案
  → ffmpeg 串流輸出 16 kHz / mono / s16le PCM（無 ffmpeg 時 WAV 走標準庫回退）
  → 滾動 VAD 緩衝（上限約 32 秒，與檔案長度無關）
  → 語音組 → processor_numpy 特徵 → OpenVINO INT8 IR → 文字
  → 每組立刻 append 寫入 SRT / JSONL + 儲存 checkpoint
  → SSE 推送結構化進度與即時字幕批次
```

記憶體占用與音訊長度無關：模型權重是固定的常駐成本，串流緩衝是固定小量，
字幕不攢到最後才寫盤。切分長度只影響上下文完整度與總耗時，不影響單段
張量形狀（特徵會被 pad 到模型匯出時的固定幀數），因此也不影響單段記憶體。

1.7B 的 audio_encoder 匯出時固定 `T=1000`，對應 10 秒上限；填入更大的值會被
夾緊，介面透過 `capabilities` 事件顯示實際生效值。

## 4. SSE 事件契約

`webview_server._EventHub` 把 `WebBackend` 的事件廣播給所有 `/api/events`
訂閱者。前端用 `window.QwenAPI.on(event, handler)` 接收。

| 事件 | 載荷 | 用途 |
|---|---|---|
| `progress` | `pct`, `status` | 相容舊版百分比進度條 |
| `progress-detail` | `pct`, `status`, `taskId`, `doneSec`, `totalSec`, `groups`, `etaSec`, `phase` | 已處理時間 / 總時長、分段數、剩餘時間、階段 |
| `segments` | `taskId`, `count`, `segments[{index,start,end,text}]` | 即時字幕；後端按 0.5 秒或 8 條節流成批 |
| `capabilities` | 生效切分長度、記憶體預估、置灰說明 | 任務開始前告知目前模式不支援的能力 |
| `vad-preview` | 段長分布、超上限比、極短段比、靜音比 | 切分預檢結果（前 5 分鐘，不跑辨識） |
| `download-retry` / `download-failure` / `download-source-switch` | `attempt`, `code`, `hint`, `file`, `provider` | 下載失敗分類與可執行的下一步 |
| `status` / `tunnel` | 模型狀態、通道狀態 | 狀態列與端點頁 |

下載類事件由 `downloader.py` 的 `set_download_event_hook()` 發出，經
`WebBackend._install_download_hook()` 轉接，不再 `print()` 到視窗版 EXE
看不見的 stdout。

`segments` 有節流是必要的：3–5 小時課程會產生上萬條字幕，逐條推事件會讓
WebView 渲染行程成為新的記憶體瓶頸。前端同樣把即時列表限制在最近 200 條，
並在使用者手動上捲時暫停自動跟隨。

進度條下方同時給出「時間 / 分段」與「百分比」兩種視圖；批次頁複用同一套
辨識參數，並把佇列總進度顯示在摘要裡。

## 5. 模型下載

`models.json` 是唯一事實來源，`model_catalog.py` 負責讀取與校驗、
`catalog_status()` 彙總狀態、`build_manifest_text()` 產生下載清單、
`import_local_bundle()` 匯入並校驗本機模型。始終使用標準庫 `urllib`，
不引入 `huggingface_hub` / `modelscope` / `hf_transfer`。

未對遠端檔案實測過的 `size_bytes` 與 `sha256` 一律為 `null`，介面顯示「未知」；
`size_hint` 是原始碼註解裡抄來的約略值，明確標註僅供參考且不用於進度計算。
鏡像切換只改寫 `huggingface.co` 前綴，GitHub 直鏈不受影響。

下載核心 `_download_file()` 支援斷點續傳、`Content-Length` 缺失時用 HEAD
探測或目錄給定大小兜底、重試退避、磁碟空間預檢、LFS pointer / HTML 錯誤頁
探測，以及把分類後的錯誤與來源切換透過事件回調送到介面。

## 6. 端點

| 類別 | 位置 |

## 7. 驗證邊界

CI 與本機回歸測試使用 mock ASR 引擎，不載入真實 OpenVINO 權重；驗證的是
調度層、落盤、中斷點、下載鏈路與前後端接線，不驗證辨識準確率。真實模型推論
需要在使用者本機執行。
