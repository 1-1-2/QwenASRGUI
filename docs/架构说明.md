# 架构说明

简体中文 · [繁體中文](架构说明.zh-Hant.md)

本文描述当前代码的**实际行为**，供后续整理项目主页时作为素材。不包含开发计划、
排期或待办事项；这些内容只在本地维护。

## 1. 窗口策略

启动器 `app_webview.py` 先在本机 `127.0.0.1` 起一个随机端口的
`WebViewServer`，再打开浏览器窗口；前端只通过 HTTP 与 SSE 与后端通信。

| 路径 | 触发条件 | 依赖 |
|---|---|---|
| Edge `--app` + `--inprivate` | **默认** | 系统自带 Microsoft Edge |
| 原生 WebView2 窗口 | 源码安装时设 `QWENASR_NATIVE_WINDOW=1` | pywebview + pythonnet + .NET |
| 默认浏览器 | 系统没有 Edge 时 | 任意浏览器 |

以前默认走原生 WebView2 窗口。散落的 DLL 从 ZIP 解压后继承
Mark-of-the-Web 标记，.NET 会拒绝加载被标记的 assembly，导致 pythonnet 失败、
窗口静默回退。当时的解决办法是把全部内容打进单个 EXE（onefile），让运行时
解压到 `%TEMP%` 从而不带标记。

现在默认走 Edge `--app`，根本不加载 .NET assembly，这条失败链不再存在。
发行包因此不再捆绑 `webview` / `pythonnet` / `clr_loader`；`build_release.py`
把它们放进 `EXCLUDE_MODULES`。标题栏配色 `_decorate_window_async()` 对两种窗口
都适用，代码原样保留。

## 2. 打包形态

当前发行包仍由 `build_release.py` 用 PyInstaller onefile 构建，但内容已按职责
区分，为后续分层留出余地：

```text
QwenASR-WebView.exe   CPython 运行时 + 全部 .py + OpenVINO / ONNX Runtime / 音频原生库
  ├─ models.json      模型下载清单的单一事实源（随 --add-data 进包）
  ├─ prompt_template.json / mel_filters.npy / silero_vad_v4.onnx
  └─ webview_assets/  前端 HTML / JS / CSS
ffmpeg/ffmpeg.exe     可选，随包附带
ov_models/            模型权重（首次启动按需下载，不内嵌）
subtitles/            输出 SRT
longform_state/       断点与逐段 JSONL
settings.json         持久化设置
```

`model_catalog.catalog_path()` 在冻结环境下先查 `_MEIPASS`、再查 EXE 同目录，
因此同一个包在未分层的 onefile 和未来的分层目录里都能工作。

EXE 体积主要来自 CPython 标准库、OpenVINO CPU plugin 与算子库、ONNX Runtime、
NumPy / SciPy 的原生扩展及 GUI 依赖。项目自身代码和前端只占很小一部分。
模型权重（0.6B 约 1.2GB / 1.7B 约 4.4GB）刻意不内嵌。

`verify_archive()` 读取 PyInstaller CArchive 目录表，确认动态导入的模块确实
进包；`model_catalog.py` 与 `models.json` 也在必需条目里。函数内动态 import
的模块若漏列，不会在启动时报错，而是点到对应功能才 `ImportError`，所以这项
校验是构建时的硬性检查。

## 3. 统一流式数据流

所有输入（GUI 单文件、批量、CLI、局域网 API）都走同一条 `LongformRunner`
路径，不再按时长分成两套逻辑。

```text
音频 / 视频文件
  → ffmpeg 流式输出 16 kHz / mono / s16le PCM（无 ffmpeg 时 WAV 走标准库回退）
  → 滚动 VAD 缓冲（上限约 32 秒，与文件长度无关）
  → 语音组 → processor_numpy 特征 → OpenVINO INT8 IR → 文本
  → 每组立刻 append 写 SRT / JSONL + 保存 checkpoint
  → SSE 推送结构化进度与实时字幕批次
```

内存占用与音频长度无关：模型权重是固定的常驻成本，流式缓冲是固定小量，
字幕不攒到最后才写盘。切分长度只影响上下文完整度与总耗时，不影响单段
张量形状（特征会被 pad 到模型导出的固定帧数），因此也不影响单段内存。

1.7B 的 audio_encoder 导出时固定 `T=1000`，对应 10 秒上限；填入更大的值会被
夹紧，界面通过 `capabilities` 事件显示实际生效值。

## 4. SSE 事件契约

`webview_server._EventHub` 把 `WebBackend` 的事件广播给所有 `/api/events`
订阅者。前端用 `window.QwenAPI.on(event, handler)` 接收。

| 事件 | 载荷 | 用途 |
|---|---|---|
| `progress` | `pct`, `status` | 兼容旧版百分比进度条 |
| `progress-detail` | `pct`, `status`, `taskId`, `doneSec`, `totalSec`, `groups`, `etaSec`, `phase` | 已处理时间 / 总时长、分段数、剩余时间、阶段 |
| `segments` | `taskId`, `count`, `segments[{index,start,end,text}]` | 实时字幕；后端按 0.5 秒或 8 条节流成批 |
| `capabilities` | 生效切分长度、内存预估、置灰说明 | 任务开始前告知当前模式不支持的能力 |
| `vad-preview` | 段长分布、超上限比、极短段比、静音比 | 切分预检结果（前 5 分钟，不跑识别） |
| `download-retry` / `download-failure` / `download-source-switch` | `attempt`, `code`, `hint`, `file`, `provider` | 下载失败分类与可执行下一步 |
| `status` / `tunnel` | 模型状态、隧道状态 | 状态列与端点页 |

下载类事件由 `downloader.py` 的 `set_download_event_hook()` 发出，经
`WebBackend._install_download_hook()` 转接，不再 `print()` 到窗口版 EXE
不可见的 stdout。

`segments` 有节流是必要的：3–5 小时课程会产生上万条字幕，逐条推事件会让
WebView 渲染进程成为新的内存瓶颈。前端同样把实时列表限制在最近 200 条，
并在用户手动上滚时暂停自动跟随。

进度条下方同时给出「时间 / 分段」与「百分比」两种视图；批量页复用同一套
识别参数，并把队列总进度显示在摘要里。

## 5. 模型下载

`models.json` 是唯一事实源，`model_catalog.py` 负责读取与校验、
`catalog_status()` 汇总状态、`build_manifest_text()` 生成下载清单、
`import_local_bundle()` 导入并校验本地模型。始终使用标准库 `urllib`，
不引入 `huggingface_hub` / `modelscope` / `hf_transfer`。

未对远端文件实测过的 `size_bytes` 与 `sha256` 一律为 `null`，界面显示「未知」；
`size_hint` 是源码注释里抄来的约略值，明确标注仅供参考且不用于进度计算。
镜像切换只改写 `huggingface.co` 前缀，GitHub 直链不受影响。

下载核心 `_download_file()` 支持断点续传、`Content-Length` 缺失时用 HEAD
探测或目录给定大小兜底、重试退避、磁盘空间预检、LFS pointer / HTML 错误页
探测，以及把分类后的错误与来源切换通过事件回调送到界面。

## 6. 端点

## 7. 验证边界

CI 与本地回归测试使用 mock ASR 引擎，不加载真实 OpenVINO 权重；验证的是
调度层、落盘、断点、下载链路与前后端接线，不验证识别准确率。真实模型推理
需要在用户本机执行。
