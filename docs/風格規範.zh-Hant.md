# 風格規範

繁體中文 · [简体中文](风格规范.md)

適用於倉庫內所有面向使用者的文件與程式註解。規則少，但每條都有原因。

## 寫法

1. **邊界前置**。先寫「不適用什麼、沒驗證什麼」，再寫功能。使用者判斷能不能用，靠的是邊界不是賣點。
2. **短句**。一句話只說一件事。避免「透過…實作了…從而…」的套疊長句。
3. **Important 區塊**用於會造成實際損失的操作（SmartScreen 未簽章、別只拷 EXE、中斷點最多丟一組）。
4. **已驗證 / 未驗證分開**，各自成節。不寫「理論上」「應該沒問題」；沒有數字就寫「未實測」。
5. **效能宣稱必附實測數字**、樣本與指令。沒有就寫「未實測」，不寫「感覺變快了」。
6. **不貼大段原文**。給結論、給路徑、給可複核的證據連結。
7. **不追加輪次筆記**。確認新事實就替換原段落；同一事實只出現一次。

## 語言

| 對象 | 約定 |
|---|---|
| 程式註解 / docstring / 測試 / workflow 註解 | 英文 |
| 使用者可見 UI 文案 | 維持三語 i18n（`hant` / `hans` / `en`） |
| 倉庫內面向使用者的文件 | **簡繁兩個獨立檔案**，每頁頂部互鏈、能去能回 |
| 產物與授權原文 | `models.json`、下載清單 `.txt`、`manifest.json`、`NOTICE` **不翻譯** |
| 提交訊息 | 簡體中文（回推上游的 PR 標題與描述用繁體） |
| 本地計畫 / 索引筆記 | 只留簡體一套，**不進倉庫** |

## 文件結構

- 頁頂第一行放互鏈：`繁體中文 · [简体中文](xxx.md)`（簡體頁反之）。
- 表格用於「能力 / 狀態」「已驗證 / 未驗證」「佈局 / 取值」這類可比較資訊。
- 程式碼區塊給出可直接複製的指令；不寫無法執行的偽碼。
- 架構圖用 Mermaid / D2 原始檔 → 明暗雙主題靜態 SVG → `<picture>` 按 `prefers-color-scheme` 切換。
  SVG 可 diff、可暗色適配，不用截圖。

## 提交與 PR

每個 PR 描述五段：**動機**（引用 issue）→ **改前 / 改後** → **驗證指令與結果** →
**相容性**（舊設定 / 舊模型目錄 / 舊中斷點）→ **回滾方式**。
UI 改動附前後截圖；新增第三方資產進 `NOTICE`；不引入 torch。

## 明確不做

- 不把計畫 / 排期 / 待辦寫進倉庫文件（歷史上曾 force push 清過一次）。
- 不為了「用滿小核 / NPU / 內顯」改 performance hint 或加多行程。
- 不恢復「整段載入 + 末尾一次性寫盤」的舊路徑（OOM 根因）。
- 不點程式內「檢查更新」用上游包覆蓋 fork。
