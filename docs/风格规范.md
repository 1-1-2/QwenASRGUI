# 风格规范

简体中文 · [繁體中文](風格規範.zh-Hant.md)

适用于仓库内所有面向用户的文档与代码注释。规则少，但每条都有原因。

## 写法

1. **边界前置**。先写「不适用什么、没验证什么」，再写功能。用户判断能不能用，靠的是边界不是卖点。
2. **短句**。一句话只说一件事。避免「通过…实现了…从而…」的套叠长句。
3. **Important 块**用于会造成实际损失的操作（SmartScreen 未签名、别只拷 EXE、断点最多丢一组）。
4. **已验证 / 未验证分开**，各自成节。不写「理论上」「应该没问题」；没有数字就写「未实测」。
5. **性能宣称必附实测数字**、样本与命令。没有就写「未实测」，不写「感觉变快了」。
6. **不贴大段原文**。给结论、给路径、给可复核的证据链接。
7. **不追加轮次笔记**。确认新事实就替换原段落；同一事实只出现一次。

## 语言

| 对象 | 约定 |
|---|---|
| 代码注释 / docstring / 测试 / workflow 注释 | 英文 |
| 用户可见 UI 文案 | 维持三语 i18n（`hant` / `hans` / `en`） |
| 仓库内面向用户的文档 | **简繁两个独立文件**，每页顶部互链、能去能回 |
| 生成物与许可原文 | `models.json`、下载清单 `.txt`、`manifest.json`、`NOTICE` **不翻译** |
| 提交信息 | 简体中文（回推上游的 PR 标题与描述用繁体） |
| 本地计划 / 索引笔记 | 只留简体一套，**不进仓库** |

## 文档结构

- 页顶第一行放互链：`简体中文 · [繁體中文](xxx.zh-Hant.md)`（繁体页反之）。
- 表格用于「能力 / 状态」「已验证 / 未验证」「布局 / 取值」这类可比较信息。
- 代码块给出可直接复制的命令；不写无法执行的伪代码。
- 架构图用 Mermaid / D2 源 → 明暗双主题静态 SVG → `<picture>` 按 `prefers-color-scheme` 切换。
  SVG 可 diff、可暗色适配，不用截图。

## 提交与 PR

每个 PR 描述五段：**动机**（引用 issue）→ **改前 / 改后** → **验证命令与结果** →
**兼容性**（旧设置 / 旧模型目录 / 旧断点）→ **回滚方式**。
UI 改动附前后截图；新增第三方资产进 `NOTICE`；不引入 torch。

## 明确不做

- 不把计划 / 排期 / 待办写进仓库文档（历史上曾 force push 清过一次）。
- 不为了「用满小核 / NPU / 核显」改 performance hint 或加多进程。
- 不恢复「整段加载 + 末尾一次性写盘」的旧路径（OOM 根因）。
- 不点程序内「检查更新」用上游包覆盖 fork。
